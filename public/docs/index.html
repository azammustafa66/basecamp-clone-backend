Overview

A RESTful backend for a collaborative project management tool inspired by Basecamp. Built with Express, TypeScript, Bun, and MongoDB.

Base URL
https://basecamp-clone-backend-1.onrender.com/api/v1
Content-Type
application/json
Auth Scheme
Bearer <access_token>
Response Shape
{ statusCode, success, message, data }

Authentication

Protected routes require a JWT access token in the Authorization header:

Authorization: Bearer <your_access_token>

Access tokens are short-lived (15m). Use POST /auth/refresh-token to rotate both tokens. Refresh tokens are single-use — reuse is detected and the family is invalidated.

Roles are project-scoped. A user can be admin in one project and member in another. The validateProjectPermission middleware sets the role per request.

adminFull control — update/delete project, manage members, all task operations
memberCreate tasks, update tasks they are assigned to or created

Auth /api/v1/auth

POST /auth/register Public Register a new user ▾
Request Body
userName*stringUnique username
email*stringMust be unique
password*stringMin 8 characters
fullNamestringOptional
Response 201
{
  "statusCode": 201,
  "success": true,
  "message": "User registered. Check your email to verify your account.",
  "data": { "user": { "_id": "...", "userName": "johndoe", "email": "..." } }
}
Notes

A verification email is queued on registration. Unverified accounts can still log in but will see isEmailVerified: false.

POST /auth/login Public Login, returns tokens ▾
Request Body
email*stringEmail or username
password*string
Response 200
{
  "data": {
    "user": { ... },
    "accessToken": "eyJ...",
    "refreshToken": "eyJ..."
  }
}
POST /auth/logout JWT Invalidate refresh token ▾

No request body needed. Clears the refresh token server-side and removes the cookie.

Response 200
{ "message": "Logged out successfully" }
POST /auth/refresh-token JWT Rotate access + refresh tokens ▾
Request Body
refreshToken*stringOr send via cookie
Response 200
{ "data": { "accessToken": "eyJ...", "refreshToken": "eyJ..." } }
Notes

Refresh tokens are rotated on every use. Reusing an old refresh token invalidates the entire token family (reuse detection).

GET /auth/verify-email/:token Public Verify email from link ▾

The token is sent in the verification email. Tokens are stored as SHA-256 hashes and expire after 24 hours.

POST /auth/resend-email-verification JWT Re-send verification email ▾

No body required. Queues a new verification email for the logged-in user.

POST /auth/forgot-password Public Request reset link ▾
Request Body
email*string
Notes

Always returns 200 regardless of whether the email exists — prevents email enumeration attacks.

POST /auth/reset-password/:token Public Reset password via token ▾
Request Body
newPassword*string

Token is single-use and expires after 24 hours.

POST /auth/change-password JWT Change password (requires old) ▾
Request Body
oldPassword*string
newPassword*string

Projects /api/v1/project

GET /project JWT List your projects ▾

Returns all projects the authenticated user is a member of.

Response 200
{ "data": { "projects": [ { "_id": "...", "name": "...", "description": "..." } ] } }
POST /project JWT Create a project ▾
Request Body
name*string
descriptionstring
Notes

The creator is automatically assigned the admin role. A confirmation email is sent to the creator.

PATCH /project/:projectId Admin Update project ▾
Request Body
namestring
descriptionstring

All project admins are notified by email when the project is updated.

DELETE /project/:projectId Admin Delete project ▾

Deletes the project and removes all membership records. The deleting admin receives a confirmation email.

Members /api/v1/project/:projectId/members

GET /project/:projectId/members Member List project members ▾
Response 200
{ "data": { "members": [ { "user": { ... }, "role": "admin" } ] } }
POST /project/:projectId/members Admin Add members ▾
Request Body
[
  { "userId": "664a...", "role": "member" },
  { "userId": "664b...", "role": "admin" }
]

Each added user receives a welcome email. Existing members are silently skipped.

PATCH /project/:projectId/members/:userId Admin Update member role ▾
Request Body
role*stringadmin | member

Admins cannot change their own role. Users promoted to admin receive a notification email.

DELETE /project/:projectId/members/:userId Admin Remove member ▾

Admins cannot remove themselves.

Tasks /api/v1/project/:projectId

GET /project/:projectId/task Member List all tasks ▾

Returns all tasks in the project sorted newest first. Includes populated assignedBy and assignedTo user objects.

POST /project/:projectId/task Member Create a task ▾
Request Body — multipart/form-data
title*string
descriptionstring
assignedTostring[]Array of user IDs
statusstringtodo | inProgress | done
attachmentsfilesMax 1MB each
Notes

Send as multipart/form-data when including file attachments, otherwise application/json. Each assignee is notified by email.

PATCH /project/:projectId/:taskId Assigner / Assignee / Admin Update a task ▾
Request Body — multipart/form-data
titlestring
descriptionstring
statusstringtodo | inProgress | done
assignedTostring[]
attachmentsfiles
Email Notifications

Status change → all current assignees notified. New assignees added → only newly added users notified.

DELETE /project/:projectId/:taskId Creator / Admin Delete task + subtasks ▾

Cascades to delete all subtasks. All assignees are notified by email.
